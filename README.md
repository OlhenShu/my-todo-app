# Лабораторна робота №2 — Компоненти та передача даних (Props)

Ця робота є продовженням першої частини та присвячена вивченню механізмів передачі даних між React-компонентами. Ми реалізуємо односпрямований потік даних від кореневого компонента `App` до кінцевих елементів списку `TodoItem`.

## Мета

- Навчитися передавати дані з батьківського компонента в дочірній за допомогою `props`.
- Опанувати деструктуризацію `props` у функціональних компонентах.
- Використовувати метод `map()` для динамічної генерації списків на основі масивів даних.
- Розуміти роль атрибута `key` при роботі зі списками в React.

## Стек і вимоги

- Node.js 18+
- Vite 7
- React 19

## Структура та ієрархія компонентів (ЛР2)

Дані передаються зверху вниз за наступною структурою:

```
App (джерело даних: tasks)
├─ Header (отримує заголовок через title)
├─ Main (прокидає масив tasks далі)
│  └─ TodoList (ітерує масив tasks)
│       └─ TodoItem (отримує окремі властивості: title, done, priority)
└─ Footer
```

## Ключові етапи реалізації

### 1. Передача даних з App
У компоненті `App.jsx` створено масив об’єктів `tasks`. Він передається в компонент `Main` як пропс: `<Main tasks={tasks} />`. Також демонструється передача простого рядка в `Header`.

### 2. Компонент-посередник Main
Компонент `Main` приймає `tasks` через деструктуризацію параметрів і без змін передає їх у `TodoList`. Це типовий приклад "прокидання" (drilling) даних.

### 3. Рендеринг списку в TodoList
Тут використовується метод `map()`. Кожен елемент масиву перетворюється на компонент `TodoItem`. Важливо: кожному `TodoItem` передається унікальний `key={task.id}` для коректної роботи React з DOM.

### 4. Відображення в TodoItem
Компонент отримує конкретні властивості (`title`, `done`, `priority`). Він використовує їх для:
- Відображення тексту задачі.
- Умовного рендерингу CSS-класів (наприклад, для закреслення виконаних задач).
- Відображення бейджів пріоритету.

## Результати
Після виконання роботи застосунок стає динамічним: інтерфейс будується на основі даних, а не жорстко прописаного HTML. Це готує базу для впровадження стану (`state`) у наступних лабораторних роботах.
