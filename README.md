# Практична робота №3 — Керування локальним станом

Ця робота присвячена вивченню механізмів керування станом у React за допомогою хука `useState`. Ми перетворюємо статичний список задач на динамічний, що дозволяє користувачу взаємодіяти з інтерфейсом.

## Що змінилося порівняно з Практичною роботою №2

| Характеристика | Практична робота №2 | Практична робота №3 |
| :--- | :--- | :--- |
| **Дані** | Статичні (звичайний масив) | Динамічні (стан `useState`) |
| **Зберігання** | Масив у `App` | Стан у `App` |
| **Взаємодія** | Лише `props` (відображення) | Події (onChange, onClick) та зміна стану |
| **Інтерфейс** | Тільки читання | Реально змінюється при взаємодії |

## Мета

- Ознайомитися з поняттям "стан" (state) у React та хуком `useState`.
- Навчитися передавати функції-обробники подій через `props`.
- Реалізувати інтерактивність: зміна статусу задачі, видалення або додавання нових елементів.
- Розуміти процес перерендерінгу компонента при зміні стану.

## Стек і вимоги

- Node.js 18+
- Vite 7
- React 19

## Структура та ієрархія компонентів (ЛР3)

Дані та функції для їх зміни передаються зверху вниз:

```
App (керує станом tasks через useState)
├─ Header
├─ Main (передає tasks та функції зміни стану)
│  └─ TodoList
│       └─ TodoItem (викликає функції зміни стану при подіях)
└─ Footer
```

## Ключові етапи реалізації

### 1. Перетворення масиву на стан
У компоненті `App.jsx` замість звичайного масиву тепер використовується `useState`. Це дозволяє React "стежити" за змінами даних і автоматично оновлювати інтерфейс.

### 2. Обробка подій
Додано функції для маніпуляції даними (наприклад, перемикання прапорця `done`). Ці функції передаються через пропси до компонентів, де безпосередньо відбувається взаємодія (наприклад, `TodoItem`).

### 3. Оновлення інтерфейсу
Завдяки тому, що дані зберігаються у стані, будь-яка зміна (наприклад, клік по чекбоксу) викликає функцію `setTasks`, що призводить до миттєвого оновлення відображення на екрані.

```

npm run dev
```
